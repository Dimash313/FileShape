### 2026-11-15 join duration hardening

A regression revealed that two 300.04-second WAV files each show 300.0s in the existing public audio probe and would pass a rounded 600-second admission check. Domain-only PR #127 now performs a supplementary exact FFprobe duration check near the 600s boundary before invoking FFmpeg. New test generates two long silent WAV files, asserts that FFmpeg is not invoked, and checks no output or scratch files remain. Isolated mixed-branch suite: 24/24 passed, not exact-head CI.

### 2026-11-15 security finding

`services.audio_tools.probe_audio` on current main can accept a text FFconcat manifest disguised as WAV, causing FFprobe to follow an additional local file. Issue #134 and draft PR #143 add early content-signature and actual-demuxer validation to prevent this. The security PR is stacked on #89 to avoid modifying its source branch. Draft #116 tests were updated to use actual tiny PCM inputs instead of nonexistent mocked probe paths; this retains compatibility with early validation. Do not activate audio join, trim, metadata or video ingestion without validating the final integrated security change and real-user isolation in all ingress routes.

### 2026-11-15 pinned-source hardening in security PR #143

An additional race was found after initial signature validation: reopening the pathname for FFprobe and again for FFmpeg can process a substituted file. Security PR [#143](https://github.com/Dimash313/FileShape/pull/143), still stacked on #89, now keeps one open validated inode for FFprobe and conversion through Linux `/proc/self/fd` and `pass_fds`. This is a Linux backend contract; no fallback to reopening a path. Two new generated silent-WAV tests change/replace the original path mid-operation and confirm the original inode is used. The old #116 timeout test now uses a real input and only simulates an FFmpeg (not FFprobe) timeout.
